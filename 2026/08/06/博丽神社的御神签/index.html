tar 符号链接漏洞的相关知识点

tar 是什么

tar 是 Linux/Unix 下的归档工具，把多个文件打包成一个 .tar 文件，通常配合压缩（gzip、bzip2 等）一起用。

符号链接是什么

符号链接（symlink）类似于 Windows 的快捷方式，就是一个文件指向另一个文件。

关于 tar 符号链接漏洞的理解

这段是官方 WP 的描述，我写个自己的理解，实则是半懂不懂感觉还要顺一下

进入后台，发现直接写了静态文件的目录是在 /app/static/，且提供了一个上传归档文件及其各种压缩形式的接口。由此我们推测此处为 tar 解包时的符号链接漏洞。

后台页面上能看到静态文件目录就是 /app/static/，上传的 tar 包会被解压到这里。tar 解压默认会保留符号链接，这就有了操作空间。我们在 tar 包里塞一个指向 ../app.py 的符号链接，解压后访问 /static/pivot 就能读到源码。

该漏洞属于任意文件写入。其核心在于系统命令 tar 在解压缩时的默认行为：跟随符号链接。

其实任意文件读取和写入都能做。读是直接访问符号链接指向的文件，写是先创建符号链接指向目标路径，再解压一个同名文件，内容就会写到链接指向的位置。这题我们先用符号链接读 app.py，后面又用同样的手法写模板文件。

顺序解压特性：tar 是按照压缩包内的文件顺序流式解压的。
跟随效应：如果在解压过程中，先在当前目录下创建了一个指向敏感路径（如 /var/www/html）的符号链接，那么后续解压出的、路径经过该链接的文件，会被 tar 顺着链接直接写入到目标敏感路径中。

  1. pivot（符号链接，指向 /app/templates/）
  2. pivot/index.html（普通文件）

解压时 tar 按顺序处理：先创建 pivot 符号链接，然后解压 pivot/index.html 时，发现 pivot 指向 /app/templates/，就把 index.html 写到了 /app/templates/index.html。顺序解压 + 跟随效应。

当前已经拿到的东西：tar 解压到 /app/static/，静态文件目录可被外部访问。

关于 Flask

看到 from flask import Flask, render_template 之前没接触过 Python Web 框架，不知道它是什么东西：

  • 它是 Python 写网站用的一个工具
  • 它有模板文件（就是 HTML），放在 templates/ 目录下

Flask 是给 SSTI 提供了一个入口。通过它，然后把恶意模板塞进去，让它执行我的代码。

对SSTI 和 XSS 的理解

XSS（跨站脚本攻击）

XSS 发生在浏览器端。一般是是攻击者在网页里塞了一段 JavaScript 代码，别的用户打开这个页面时，浏览器把那段代码执行了。

很多题输入 <script>alert(1)</script>，尝试验证漏洞是否存在

SSTI（服务端模板注入）

SSTI 发生在服务器端。攻击者在模板里塞了一段代码，服务器上的模板引擎（这道题里的 Jinja2）把它当成代码执行了。结果是服务器自己执行了我的命令。代码在服务器上执行，攻击目标是服务器。

XSS 常见于评论区、搜索框这些用户输入的地方；SSTI 常见于模板渲染、页面生成。
